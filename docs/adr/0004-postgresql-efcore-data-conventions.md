# ADR-0004: PostgreSQL, EF Core and data conventions

**Status:** Accepted
**Date:** 2026-11-04

## Decision
- **Database:** PostgreSQL. The exact version is fixed in the deployment guide (target 16 or later). Integration tests run against real PostgreSQL through Testcontainers.
- **ORM:** EF Core migrations with the Npgsql provider (PostgreSQL licence, permissive).
- **Naming:** snake_case for tables and columns, configured through EF naming conventions.
- **Keys:** `id uuid`, generated by the application, on every table.
- **Standard columns on every business table:** `tenant_id uuid`, `created_at timestamptz`, `created_by uuid`, `updated_at timestamptz`, `updated_by uuid`, `row_version bigint`. Configuration tables also carry `is_active boolean`.
- **Optimistic concurrency:** `row_version` is incremented by a SaveChanges interceptor and used as the EF concurrency token. It is exposed as the ETag (ADR-0007).
- **Money:** `numeric(18,2)`. **Rates:** `numeric(18,4)`. Never `float` or `double`.
- **Time:** `timestamptz`, stored in UTC (ADR-0008).
- **Soft delete:** only where deletion is allowed (unused configuration records). Request and audit tables are never deleted.
- **Ranges:** PostgreSQL `numrange` with lower bound exclusive and upper bound inclusive (`'(]'`). Overlap is prevented by an `EXCLUDE USING gist` constraint. This needs the `btree_gist` extension for equality on `tenant_id`.
- **Partial unique indexes** enforce single-holder designations (CEO, CFO, Head of Admin & GST), one active department-head limit per nature, one active rate per currency, and one active rule per nature, category and subcategory.
- **CHECK constraints** enforce integrity only: minimum below maximum, minimum approvals not above required members, amounts above zero, and checker not equal to maker.
- **No business rules in stored procedures.** The database enforces integrity; the application decides.
- **Migrations and seed data** run on deploy through a dedicated migration step. The application database account has only the rights the module needs. The audit tables allow insert and select only (ADR-0005).

## Consequences
- Constraints that EF cannot express well (range exclusion, partial indexes) are added as raw SQL in migrations and tested in integration tests.
