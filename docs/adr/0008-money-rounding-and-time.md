# ADR-0008: Money, rounding and time handling

**Status:** Accepted (rounding default pending Part 18 item 23)
**Date:** 2026-11-04

## Decision
- **Types:** `decimal` in C# and `numeric(18,2)` in PostgreSQL for money. `numeric(18,4)` for exchange rates. Never `float` or `double`.
- **Rounding:** PKR amount = approval amount × active rate, rounded to two decimals with `MidpointRounding.AwayFromZero` (Part 4.1, and the default for Part 18 item 23).
- **Comparison:** limits and ranges compare the rounded PKR amount.
- **Exchange-rate snapshot:** the request stores currency code, rate, rate record id and timestamp.
- **Time:** stored as `timestamptz` in UTC and displayed in **Asia/Karachi**. Conversion happens in the formatting layer, not in the browser's local zone.
- **Date format:** `dd-MMM-yyyy` (Part 19).
- **Digit grouping:** user-selectable, international (1,000,000) or lakh and crore (10,00,000). The default is to be confirmed.
- **Amount in words:** generated by a tested converter for PKR, with a documented rule for paisa.

## Consequences
- A property-based test suite covers rounding boundaries (Part 16).
